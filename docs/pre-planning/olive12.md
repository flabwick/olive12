## Problems

Ultimately I think that chat interfaces are outdated. I currently have a workflow which connects by written work on Obsidian with a chatbot like claude or chatgpt. It sucks, but no app exists that's any better. That's why I want to create it. I want to create it because I want it to exist, not because I want to necessarily be an entrepeneur or startup tech founder, although I do want to be smart.

The chat interface is not optimised for knowledge work. 

Real knowledge work isn't a linear exchange — it's iterative. It involves building up context over time, refining ideas, navigating between related concepts, and transforming information into something new. Chats treat everything you've ever said as equally weighted context buried in an endless scroll. When you think using a chat it feels like a log that you refer to, and referring to logs is not the same as thinking.

The interface should be a workspace you inhabit and navigate, that you re-read, reconstruct and refine over time. Almost like a web browser where you can scrape through your file system and dynamically compose context windows and prompt AI for stuff, then index outputs and drafts and stuff.

Mixing and matching context with complex prompts.
- Right now what I do is I have the chat interface, and if I want to link a full document I click the link file button, search through my file system (could just have a searchbar with indexing but not, android embed file thing is pretty primitive and unintuitive).
- Doesn't work that well with edits. Once I upload a file into the chat, it can't be changed. I have to restart the chat entirely. Say I rewrite the document I link into it, like maybe i'm iterating on an essay and I've just rewritten it. I either have to upload the new one in a new message with the old one clogging up context, or I have to restart. Also hard to see things in the chatbot and then apply edits in the text editor, especially on the phone. I use obsidian and switching between chat and obsidian and copying and pasting passages and stuff is a goddamn nightmare. Little easier on desktop but sometimes I want to study or write or read interactively on the train or in bed without my computer out.
- Embedded chatbots are getting the wrong idea. Things like google docs with the gemini chat on the side. Switching back and forth between isn't intuitive and sucks, interface should allow you to see both in the same interface, switch between when you want but also make it really easy to transfer stuff between the AI and the actual files you're working on and editing, then also being able to actively edit and update the context window as you're working through it

Transparency
- Fully automated thinking systems like Manus or fully automated prompt compiling systems like Claude projects or RAG in general doesn't actually show you what context it's using. It's a black box which is theoretically liberating but in practice you've handed the wheel to something you can't see. When AI gets things wrong or gets some ideas from sources you didn't want it to be reading and you have no idea where the mistake entered the chain. There's a stress about auditing outputs. You should have control from a defined set of actions that are intuitive and give you the freedom.

Writing and journaling without things getting over cluttered. AI organising zettelkasten which helps keep things separated but also linked, easily findable but not rigid like file folder structures. Use of the file system should be like a second brain where the different files are opened together than the relationships grow and get more interlinked like a persistent, compounding artifact. Standard RAG rediscovers things from scratch every time, but auto tags and auto indexing can be done by AI and inferred from which files are opened together and what the prompts are that relate to it, can auto-maintain itself in the background. 

Brainstorming and testing ideas - interactive reading. One thing I like doing is taking a long passage like a chapter from an article I'm reading or a long chatgpt response that I've asked and then ask questions. I might write 10 questions in a loose note on a different tab somewhere. Then I either copy and paste them all in the chat which has mixed results, or I go one by one trying out the ideas by pasting one in, then going back and forth between the notes and the llm editing the message to replace it with the different idea. Then I get another note and write down more notes and questions which are separate like things I like which I want to be added to the wider context and then temporary things like ideas and questions which I want to put in when I'm addressing them specifically. Another thing is uploading files I might have 5 1000 word journal entries in my files which I want to test the same way with whatever context I already have, see what insights come from combining them. This is incredibly difficult and high friction right now. There should be some way to merge the chat interface itself with the file system, allow editing but also have a middle ground where I can hold these files and blocks of text where they're neither cluttering my files or cluttering the context so I can pass things and mix and match.

Merging, splitting and formatting using AI. AI is really good at these three things but they all require the same connection to the file system. For instance I might have 20 loose note sets from different days or weeks like journal entries, vomit drafts, notes in general. It's common for me to merge them in a way by copying and pasting them all one by one into the chat (since they usually don't allow more than 5 files uploaded in a message) which takes a while, then asking AI to respond by compiling the ideas, picking out themes and organising them together. Then I might get a separate loose document and go back and forth between that and the chat, asking for more information in certain places, then writing separately on this other app. Again, convoluted and spread across apps. Same thing with a long document I might want to extract or split certain aspects, like take out all the content relevant to another file, then ask AI for insights then write something else separately. Another thing is formatting, I might have a speech to text thing or an extremely rough draft and I just want it spell checked or formatted properly from docs to markdown or PDF to text or web clipping to markdown whatever it is, AI can do this but it's annoying having to compile the prompts constantly, describe in words waht I want, downloading and organising the inputs and outputs separately.

Optimised integration with speech to text and handwriting to text. Right now OCR software doesn't do a great job at taking note of handwriting which is complex and badly formatted, but AI is really good with multimodal support. I find myself using the cheapest one something like gemini or qwen, taking the photos, then taking the output in whatever format and trying to load it into obsidian.

## The solution

The system is like a web browser but instead of browsing the web you're browsing your **vault**, which is essentially a database.

The system works in tabs, similar to a web browser. Each tab contains **cards**. You can create them or open them from the vault. Then you can edit them, remove/delete them, save them, reorder them. Cards are quite versatile things. You can save cards into the vault, and you can also save tabs into the vaults as well. Cards have a (+) button which allows you to save them to the vault. Then they are added to the SHELF. The shelf is a section of the vault which is chronological, meant to just be a place you dump everything that you want saved but not necessarily organised rigidly. Then once within that you can then move them from the shelf into the library, which is a much more organised bank. To be explained later.

Card ideas
- Text cards. The most basic type. Includes a title and content. Can be saved into the vault. Becomes little units of context. Can include embed links to other cards (also in their portal forms) which can then be opened within the tab. So a text card could just be a bunch of links to other cards, which might have their own links. You can then open them recursively. Can also click fold and unfold, and also hide which shows and hides it from the context window to prevent recursive clutter.
- Other content cards: Whatever file types, could be code files, different file processes, images, whatever.
- Process cards. Lots of potential here, runs some process. Could be taking the tab content and sending a certain prompt to AI, could be running a web search, could be running some code process or software like OCR or file transferring or whatever. Theoretically could be anything. The idea is it's really good at transforming the card information between formats and then good for creating pipelines. Designed to be really intuitive and easy to use but have the same ultimate capabilities as long code files. People should be able to run automations and stuff with it. Kind of like how Excel makes maths and modelling easier and intuitive this does the same for automation, coding and LLM agentic stuff. There are a bunch of primitives that could exist that have preset coding and processes and stuff.  Card might include a bunch of preset code which requires inputs like parameters which you can type yourself or you can ask the dock to write for you.
- Portal cards. Contain links to cards that exist in the vault either the shelf or the library. The idea is it's like a portal to that content, you can use the tab to make edits to it and it will sync to the vault and to every other tab that includes the portal to that same file. 
- Transient cards. Don't actually exist in the context window like the dock doesn't read it as context when writing new cards and stuff. Could be a search bar for adding cards to the thread, whatever. Important to have this middle ground.
- FLIPPING CARDS. There's a function to flip a card which includes the metadata and wiki. Includes the programming and the parameters set if it's like a process card, or the path to the vault card if it's a portal, and if it's in the library it also includes a view of the wiki index entry and the option to edit it.
- Container cards. Can be created by dragging a card onto another card, then creates a container with it. Different kinds of containers. Containers which just includes all of the cards within at all times, useful for rank polymorphism for instance a process might link to the content of the container so by linking to it it will either do the process once for all of the cards or do the process recursively for all of them individually and then output a container which includes all the outputs. Container could also be tab-based, so you can scroll through and mix and match easily different cards in that slot.

NOTE: cards can be folded and hidden from context using a folding and eyeball icon. To prevent clutter and maintain control in the tab feed of the cards.

Dock. The dock is a sticky footer at the bottom which has two tabs you can flip between
- Prompt: this allows you to type prompts to an LLM which uses all of the cards in the tab as context. Can write new cards and propose edits to existing cards in there, requires approval to make the changes each time like there's approve and deny each card and then deny all approve all from the dock as well. Can also make a prompt by linking directly to a certain card so that it only edits that given card instead of generating new ones.
- Dock: Includes any number of tabs where you can type draft cards, drag cards from the tab onto and from the dock. The idea is it's a middle ground where you can traverse different tabs and have a place where you can keep stuff in between. Good for notes you don't want in the context window or when you're reordering cards in between tabs.

Brain.
- Intended to be the most organised zettlekasten-style vault in the world. Inspired by Karpathy's wiki-llm. Files are indexed by links and tags.  The brain/library includes a Wiki section. The wiki section is a condensed index which maps one-to-one to all the cards in the library/brain. Every card in the library/brain has a `index_entry`, which is a short machine-written block (title, tags, 1-2 sentence summary, links to other cards, content hash). When a card is moved to the library, the Wiki LLM reads the content of the card and all of the index entries and then writes an index entry. Should never read full card bodies, except the one card currently being processed.
- Then there is a Brain feed which is a standing tab. The system flags things in here for maintenance. Feed card sends a prompt to the Wiki LLM for the maintenance, requires accept/dismiss/edit input. Nothing is silently rewritten — the feed is the only path to a Library write outside of promotion.
	- Staleness: content hash mismatch between source and wiki using sql.
	- Suspected contradictions
	- orphans (zero links in or out)
- Also note, when the dock or transient cards search the library/brain for relevant cards or context search it will search the wiki index entries not the full body context.

Smart tabs
- A different type of tab that works differently to blank tabs but using the same interface. Blank tabs are entirely self-built, you build the context window and use the tools as you see fit. theoretically powerful but also daunting. Smart tabs are different, it works like a form you fill out that the LLM figures out for you. The LLM knows about all of the functionality of the cards and then it will ask for your input with prompts, buttons, that type of thing. Adjusts and rebuilds the feed based on what you want, build whatever it needs, gives suggestions, etc. Like a conversation with a living form to fill out as you go along. Here you can get creative.
